# Chrome Bookmarks Manager v1.2.0

V1.2.0 adds native Chrome `Bookmarks` drag-and-drop loading and a complete bulk bookmark import workflow while preserving the existing bilingual interface, large-library behavior, Undo/Redo model, and guarded Safe Save protections.

## Highlights

- Drag a Chrome native file named `Bookmarks` directly onto the application to load it.
- External drop is intentionally strict: unrelated files, including `Bookmarks.bak`, HTML, TXT, and JSON files, are not treated as native Chrome Bookmarks input.
- Add many bookmarks at once by entering one URL per line.
- Import UTF-8 TXT files containing one URL per line.
- Accepted bare host/path inputs are normalized with `https://`.
- Invalid input reports the affected line numbers and blocks the complete batch; partial import is not allowed.
- Each successful batch is recorded as one Undo/Redo history operation.
- Bulk-add entry points are available from:
  - Edit -> Add Bookmarks in Bulk...
  - the left folder-tree context menu
  - the right contents-pane context menu
- Both left and right entry points add into the current folder and share the same import, validation, and history implementation.

## Safety

V1.2 does not weaken the existing Safe Save boundary.

- Loading by drag-and-drop uses the same document-load path and dirty-document protection as File -> Open.
- Editing remains in memory until the user explicitly saves.
- Chrome must be fully closed before a real Safe Save.
- Source-baseline conflict detection remains active.
- Application-owned backup verification remains active before atomic replacement.
- Chrome's own `Bookmarks.bak` is not repurposed as the application's backup.
- Invalid bulk input is all-or-nothing and cannot partially mutate the document.
