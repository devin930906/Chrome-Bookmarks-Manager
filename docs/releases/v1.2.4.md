# Chrome Bookmarks Manager v1.2.4

## Critical serialization fix

V1.2.4 fixes a serious Save regression found with a real large Chrome `Bookmarks` library.

The previous writer could make a small logical edit look like a full-file rewrite because it serialized the document using .NET's default JSON presentation instead of Chrome's native text format. On a large real-world file this also caused major size inflation because non-ASCII text was emitted as `\uXXXX` sequences.

## Changes

- Added Chromium-native `Bookmarks` text serialization:
  - three-space indentation;
  - CRLF line endings;
  - Chrome-style inline child arrays such as `[ { ... }, { ... } ]`;
  - Chrome-style property ordering;
  - raw UTF-8 Chinese / Unicode text instead of blanket `\uXXXX` conversion;
  - preservation of Chrome's `< -> \u003C` escaping behavior.
- MD5 `checksum` is still regenerated on every explicit Save.
- `checksum_sha256` is now regenerated only when the loaded source already contains that field. MD5-only Chrome files remain MD5-only instead of gaining a new top-level property.
- Preserved all verified Safe Save protections: source-baseline conflict detection, validated temporary output, verified backup, atomic replacement, post-write validation, and recovery reporting.
- Added byte-level regression coverage for native formatting and Unicode behavior.
- Added persistence coverage for MD5-only source files.
- Retains all v1.2.3 functionality, including right-pane **Add Bookmark...** and saving detached `Bookmarks` copies while Chrome is running.

## Why this matters

For an unchanged Chrome-native document, the serializer is now designed to reproduce Chrome's native textual shape instead of normalizing the entire file into a different JSON presentation. Actual edits should therefore produce localized differences instead of massive formatting noise and unnecessary file growth.
