# Chrome Bookmarks Manager V0.3 Browser UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use the Superpowers subagent-driven development workflow for implementation. Execute one task at a time with TDD evidence, focused commits, and an independent spec/code review before advancing.

**Goal:** Turn the completed V0.2 read-only reader into a usable, read-only bookmark browser that exposes Chrome's folder hierarchy and the selected folder's direct bookmark URLs without materializing one WPF control per bookmark.

**Architecture:** Keep the V0.2 domain model as the source of truth. Add thin WPF presentation state for folder-tree nodes only, bind the bookmark list directly to existing `BookmarkUrl` domain instances, and keep browser selection/state inside `MainViewModel`. The UI never reparses JSON and V0.3 still exposes no writer, editor, search index, delete, move, reorder, or save path.

**Tech Stack:** C# 14, .NET SDK 10.0.401, `net10.0-windows`, WPF, xUnit 2.9.3, PowerShell 7, GitHub Actions Windows runner.

**Spec:** `docs/superpowers/specs/2026-09-19-chrome-bookmarks-manager-design.md`

**Baseline:** V0.2 is merged to `main` at `840d12dcebe0ac9850c9db66df7dc0540db690ed`. Windows 10 owner acceptance loaded 209,382 URLs and 3,404 folders in 1.8 seconds with SHA-256, length, and last-write timestamp unchanged.

## Global Constraints

- V0.3 remains strictly read-only.
- Do not add bookmark editing, rename, add, delete, move, reorder, drag/drop, Undo/Redo, writer, checksum generation, backup, replacement, or save behavior.
- Do not implement search or an in-memory search index; those belong to V0.4.
- Never commit, upload, log, screenshot, or embed private bookmark titles/URLs from the owner's real file.
- The domain model remains the source of truth; UI presentation state must reference domain nodes rather than clone bookmark payloads.
- Never create one WPF control for every bookmark.
- The bookmark `ListView` must use UI virtualization and recycling.
- The folder `TreeView` must start collapsed/minimally expanded; no automatic expand-all.
- The tree presentation layer may create one lightweight wrapper per folder because the real baseline is ~3,404 folders, but must not create wrappers for ~209k URL nodes.
- Selecting a folder exposes that folder's **direct URL children only** in the right-hand bookmark list. Child folders remain represented by the left-hand tree.
- Preserve original child ordering. V0.3 visual browsing must not alter persisted order.
- Browser state must clear atomically before a new load and remain empty after cancellation or read failure.
- Long file loading remains asynchronous and cancelable exactly as in V0.2.
- The source Chrome `Bookmarks` file must remain byte-for-byte unchanged.
- Existing V0.1/V0.2 repository-safety, tests, single-file publish, startup smoke test, and artifact gates must remain green.
- No new NuGet dependency is permitted unless separately justified and reviewed.

## V0.3 UX Contract

After a successful load:

1. the tree shows exactly three top-level roots in this order:
   - bookmark bar
   - other bookmarks
   - synced/mobile bookmarks
2. the roots use names from the parsed Chrome document rather than hard-coded English labels;
3. the tree contains folder nodes only;
4. the bookmark bar root becomes the initial selected folder;
5. the right list shows only direct `BookmarkUrl` children of the selected folder;
6. list ordering matches domain child ordering;
7. selecting another tree folder immediately replaces the right list;
8. the selected bookmark may be represented as a single selection in V0.3;
9. multi-select/batch semantics remain deferred to V0.7;
10. status UI exposes document counts, selected-folder direct bookmark count, load/status state, and local source path;
11. search remains visibly disabled with the V0.4 message;
12. editing menus/actions remain disabled.

## Review Focus

1. A 209k-node document must not become 209k WPF controls.
2. Folder wrappers must never recursively wrap URL nodes.
3. `CurrentBookmarks` must hold/reference existing `BookmarkUrl` objects, not deep-copy URL/title/meta data.
4. Tree/list selection must never mutate the domain hierarchy.
5. Load failure or cancellation must not leave the previous document's tree/list visible.
6. Programmatic initial root selection must not auto-expand the entire tree.
7. XAML virtualization settings must be mechanically verified in CI.
8. V0.3 must preserve the V0.2 read-only source-file invariant.

**Interfaces:**

`FolderTreeItemViewModel` is a lightweight presentation wrapper around one `BookmarkFolder`.

Required public shape:

```csharp
public sealed class FolderTreeItemViewModel : ViewModelBase
{
    public FolderTreeItemViewModel(BookmarkFolder folder);

    public BookmarkFolder Folder { get; }
    public string Name { get; }
    public IReadOnlyList<FolderTreeItemViewModel> Children { get; }

    public bool IsExpanded { get; set; }
    public bool IsSelected { get; set; }
}
```

Rules:

- `Folder` is the original domain instance.
- `Name` delegates to `Folder.Name`.
- `Children` contains only direct child folders, preserving domain order.
- URL children do not produce tree wrappers.
- All nodes start `IsExpanded == false`.
- All nodes start `IsSelected == false`.
- `IsExpanded` and `IsSelected` raise `PropertyChanged` only when the value actually changes.
- Do not copy extension data, timestamps, URLs, or other bookmark payloads.

### Task 2: Add browser state and folder selection to MainViewModel

**Files:**
- Modify: `src/ChromeBookmarksManager/ViewModels/MainViewModel.cs`
- Create: `tests/ChromeBookmarksManager.Tests/Browser/MainViewModelBrowserTests.cs`

**New MainViewModel surface:**

```csharp
public IReadOnlyList<FolderTreeItemViewModel> FolderRoots { get; }
public BookmarkFolder? SelectedFolder { get; }
public IReadOnlyList<BookmarkUrl> CurrentBookmarks { get; }
public BookmarkUrl? SelectedBookmark { get; set; }
public bool CanBrowseDocument { get; }
public string DocumentSummaryText { get; }
public string SelectionSummaryText { get; }

public void SelectFolder(FolderTreeItemViewModel? item);
```

**State rules:**

- Before load: roots/list/selection are empty.
- Starting a new load clears all browser state before changing to `Loading`.
- Successful load:
  - builds exactly three root wrappers in `bookmark_bar`, `other`, `synced` order;
  - marks the bookmark-bar wrapper selected;
  - sets bookmark bar as `SelectedFolder`;
  - exposes direct bookmark URLs from bookmark bar as `CurrentBookmarks`;
  - preserves domain child order.
- Folder changes:
  - set `SelectedFolder` to the wrapper's original domain folder;
  - set exactly one tree item selected;
  - clear `SelectedBookmark`;
  - replace `CurrentBookmarks` with direct URL child references only.
- Cancellation/failure:
  - no document;
  - no root wrappers;
  - no selected folder/bookmark;
  - no current bookmark rows.
- `CanBrowseDocument` is true only in loaded document states.
- V0.3 remains compatible with future `LoadedDirty` even though V0.3 never creates dirty state.

**Summary text contract:**

After load:

```text

```

For selection:

```text
<Folder Name> | <N> bookmarks
```

Do not include individual private bookmark titles/URLs in status text or logs.

## Self-Review Notes

### Scope discipline

V0.3 is deliberately limited to browsing. Search/index, editing, movement, deletion, Undo/Redo, and persistence remain assigned to later milestones.

### Large-data strategy

The domain already contains URL nodes from V0.2. V0.3 adds only folder wrappers (~3,404 on the real baseline) and a selected-folder reference list. WPF item containers are virtualized/recycled so ~209k URLs do not become ~209k simultaneous UI controls.

### Selection semantics

V0.3 supports a selected folder and a selected bookmark. Multi-selection/batch behavior remains V0.7 to avoid accidentally defining editing semantics early.

### Privacy

Real bookmark titles/URLs remain local. CI and committed tests use synthetic reserved-domain data only.

### Completion rule

Do not mark V0.3 complete and do not merge its PR until automated gates and Windows 10 owner acceptance both pass.
