# Chrome Bookmarks Manager V0.4 Search / Index Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use the Superpowers subagent-driven development workflow. Execute one task at a time with RED → GREEN → REFACTOR evidence, focused commits, and an independent spec/code review before advancing.

**Goal:** Add fast, read-only in-memory bookmark search to the completed V0.3 browser without rereading the Chrome `Bookmarks` file, without cloning bookmark payloads, and without weakening the existing virtualization or read-only guarantees.

**Architecture:** Build one immutable search index from the validated V0.2/V0.3 `BookmarkDocument` after file parsing and before the document becomes fully loaded. The index stores original `BookmarkUrl` references in stable document order. Search work runs off the WPF UI thread, supports cancellation, and returns original domain references. `MainViewModel` owns debounced search state and exposes one virtualized bookmark list for either the selected folder or active search results. Result navigation resolves the bookmark's existing parent folder back to the V0.3 tree wrapper, expands only the required ancestor path, selects the folder, and selects the original bookmark.

**Tech Stack:** C# 14, .NET SDK 10.0.401, `net10.0-windows`, WPF, `System.Text.Json`, xUnit 2.9.3, PowerShell 7, GitHub Actions Windows runner.

**Spec:** `docs/superpowers/specs/2026-09-19-chrome-bookmarks-manager-design.md`

**Baseline:** V0.3 is complete on `main`. Release-plan closeout commit: `ac8c7a9b14afc1817d6db95cc6f5250c624c6dae`. V0.3 post-merge and closeout GitHub Actions runs #57 and #58 passed. The real private baseline is 209,382 URLs / 3,404 folders.

## Global Constraints

- V0.4 remains strictly read-only.
- Do not add bookmark editing, add, rename, delete, move, reorder, drag/drop, Undo/Redo, save, writer, checksum generation, backup, replacement, or Chrome write-back.
- Search must never reread the source `Bookmarks` file.
- Search must operate only on the already validated in-memory domain model/index.
- Search results must reference existing `BookmarkUrl` instances; do not clone URL/title/metadata payloads.
- Do not allocate normalized copies of every bookmark name/URL merely for convenience unless measurement proves the extra memory is justified.
- Use ordinal case-insensitive substring matching in V0.4.
- A query matches when it appears in bookmark `Name` or `Url`; domain text is therefore naturally covered by URL substring matching.
- Trim leading/trailing whitespace from the query.
- An empty/whitespace query means search is inactive and the right pane returns to normal V0.3 selected-folder browsing.
- Preserve document order in search results.
- `CurrentFolder` scope means **direct URL children of the currently selected folder only**, matching V0.3's right-pane semantics. It does not recursively include descendant folders.
- `AllBookmarks` scope searches all URL nodes across the three Chrome roots.
- Search input must be debounced.
- A newer query/scope/folder change must cancel or supersede stale search work.
- Stale results must never overwrite results for a newer query.
- Search and index construction must not permanently block the WPF UI thread.
- Existing V0.3 TreeView/ListView virtualization and recycling must remain enabled.
- Search results with tens or hundreds of thousands of matches must not materialize one WPF control per result.
- Search must not log private titles, URLs, query text, or result payloads by default.
- The private real `Bookmarks` file must never enter GitHub, CI, logs, committed fixtures, or documentation.
- No new NuGet dependency is permitted unless separately justified and reviewed.

## V0.4 Search UX Contract

After a document loads successfully:

1. the search box becomes enabled;
2. default search scope is `All bookmarks`;
3. the normal right pane continues to show direct bookmarks from the selected folder while the search query is empty;
4. typing a non-empty query waits for the debounce interval, then searches asynchronously;
5. search results replace the normal right-pane rows while search is active;
6. results use the same Name / URL columns and existing virtualized ListView;
7. the status bar exposes match count and search state without displaying query text;
8. clearing the query restores the selected folder's normal direct-bookmark list;
9. changing scope while a query is active reruns the search;
10. changing folder while `Current folder` scope is active reruns the search for the new folder;
11. changing folder while `All bookmarks` scope is active does not change the global search result set;
12. a stale slower search may never overwrite a newer search;
13. activating a search result navigates to its existing parent folder, expands only the ancestor chain needed to reveal that folder, selects the folder, selects the original bookmark, and clears search mode;
14. search never mutates bookmark hierarchy or persisted order.

## Search Semantics

V0.4 deliberately implements predictable substring search rather than fuzzy ranking.

- comparison: `StringComparison.OrdinalIgnoreCase`
- fields: `BookmarkUrl.Name`, `BookmarkUrl.Url`
- Chinese/Unicode text: supported as substring text
- URL schemes: treated as opaque strings exactly as V0.2 does
- result ordering: original document order
- no scoring/ranking
- no fuzzy matching
- no stemming
- no tokenization
- no online lookup
- no favicon/network access
- no regex mode
- no duplicate-URL analysis in V0.4

**Construction/testability:**

The debounce duration must be injectable or internally testable. Production default: **250 ms**. Unit tests may use zero/small deterministic delay.

An internal test seam such as `WaitForPendingSearchAsync()` is permitted because `InternalsVisibleTo("ChromeBookmarksManager.Tests")` already exists. Do not expose test-only controls in the public UI API.

**Load integration:**

A successful V0.4 load is:

```text
Reading Bookmarks...
→ validated BookmarkDocument
→ Building search index...
→ complete BookmarkSearchIndex
→ build V0.3 browser state
→ LoadedClean
```

Rules:

- the search index is built from the newly read document before full loaded state is exposed;
- cancellation applies to both file reading and index construction;
- failure/cancellation clears document, browser state, search index, query/results, and selection atomically;
- a new file load cancels/clears pending search work;
- no previous document search result may survive into the next document.

**Debounce/latest-wins rules:**

- setting `SearchText` schedules search after 250 ms;
- a newer SearchText cancels the previous pending debounce/search;
- changing `SearchScope` with an active query reruns immediately or with a fresh debounce, but stale results must not win;
- changing selected folder with active `CurrentFolder` search reruns for the new folder;
- changing selected folder under `AllBookmarks` does not unnecessarily rerun the global query;
- clearing SearchText cancels pending work, clears SearchResults, sets `IsSearchActive=false`, and restores `DisplayedBookmarks=CurrentBookmarks`;
- only the latest search generation may publish results.

**Status rules:**

Examples:

```text
Searching...
12 matches
No matches
```

Do not place the private query text or result titles/URLs into status/log output.

## Self-Review Notes

### Scope discipline

V0.4 adds search/index/navigation only. Editing remains V0.5, movement V0.6, deletion/batch V0.7, Undo/Redo V0.8, and production persistence V0.9.

### Memory strategy

The initial index stores URL references rather than normalized duplicates of every title/URL. Search uses ordinal case-insensitive comparisons directly against domain strings. If later measurements prove more indexing is needed, optimize with evidence rather than speculation.

### Current-folder definition

V0.4 defines current-folder search as direct bookmark children only. This deliberately matches the V0.3 right-pane model and avoids silently redefining current-folder scope as recursive subtree search.

### Race safety

Debounce alone is insufficient. Every search generation must be cancelable/supersedable, and publication of results must be guarded so an older slower operation cannot overwrite newer results.

### Privacy

Search tests and scale measurements use synthetic data only. Private query text, titles, URLs, and raw bookmark data stay local.

### Completion rule

Do not mark V0.4 complete and do not merge its PR until automated gates and Windows 10 owner acceptance both pass.
