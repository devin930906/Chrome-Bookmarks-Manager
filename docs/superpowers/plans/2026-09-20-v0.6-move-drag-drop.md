# V0.6 Move / Reorder / Drag & Drop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add browser-like bookmark/folder move, reorder, drag-and-drop, and Move to... behavior while keeping V0.6 strictly in-memory.

**Architecture:** Preserve `BookmarkFolder.Children` as a read-only public surface, add narrow internal child-mutation primitives, and route every move through a dedicated `IBookmarkMoveService`. MainViewModel orchestrates dirty state and projection refresh; WPF translates drag/drop and Move to... user gestures into service calls without mutating the domain directly.

**Tech Stack:** C# / .NET 10 / WPF / XAML / xUnit / GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-20-v0.6-move-drag-drop-design.md`

## Global Constraints

- Target Windows 10 / Windows 11 x64.
- Preserve the existing left folder tree + right bookmark list layout.
- V0.6 supports both Drag & Drop and Move to....
- Move to... appends to the end of the selected target folder.
- Permanent Chrome roots are destinations but never movable sources.
- Folder self/descendant moves are forbidden.
- Moves preserve object identity, ID, GUID, metadata, timestamps, URL, descendants, and document counts.
- V0.6 is in-memory only; no source-file write, Save, checksum, backup, replace, or Chrome process handling.
- Real private bookmark data must never enter the repository or CI.
- Use RED -> GREEN TDD for behavior changes.

## Review Focus

- Same-parent moves where removing the source shifts the requested insertion index: final order must be exact and never off by one.
- Mixed child sequences containing folders and bookmarks: bookmark-only reorder must not accidentally reorder folders, and folder-only reorder must not accidentally reorder bookmarks.
- Folder cycles through deep descendants: every descendant depth must be rejected, not only direct children.
- Search mode: cross-folder moves remain valid, while positional reorder from global/current search results must be rejected because result order is not folder order.
- No-op movement: must not mark a clean document dirty or trigger unnecessary projection/index work.

```csharp
internal int IndexOfChild(BookmarkNode child)
{
    ArgumentNullException.ThrowIfNull(child);
    return _children.IndexOf(child);
}

internal BookmarkNode RemoveChildAt(int index)
{
    var child = _children[index];
    _children.RemoveAt(index);
    child.Parent = null;
    return child;
}

internal void InsertChild(int index, BookmarkNode child)
{
    ArgumentNullException.ThrowIfNull(child);

    if (child.Parent is not null)
    {
        throw new InvalidOperationException(
            "A bookmark node with an existing parent cannot be inserted as a child.");
    }

    _children.Insert(index, child);
    child.Parent = this;
}
```

Do not expose mutable collections.

private static bool IsDescendantOf(
    BookmarkFolder candidate,
    BookmarkFolder ancestor)
{
    BookmarkFolder? current = candidate;
    while (current is not null)
    {
        if (ReferenceEquals(current, ancestor))
        {
            return true;
        }

        current = current.Parent;
    }

    return false;
}
