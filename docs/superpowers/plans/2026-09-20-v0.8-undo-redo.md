# V0.8 Undo / Redo Implementation Plan

> **Execution model:** Superpowers-style task-by-task development with RED -> GREEN evidence, focused commits, Windows CI, whole-branch review, Windows 10 owner acceptance, merge, and post-merge verification.

**Goal:** Add safe, deterministic, session-local reversible mutation history for V0.5–V0.7 operations while preserving the no-write safety boundary.

**Baseline:** V0.7 completed on `main` at `a7d2c27213b76cc0a295c4e7f46e09987f71878c`.

**Spec:** `docs/superpowers/specs/2026-09-20-v0.8-undo-redo-design.md`.

## Global constraints

- Windows 10 / Windows 11 x64.
- .NET 10 / WPF / C#.
- V0.8 remains in memory only.
- No source Chrome Bookmarks write/delete/replace/backup/checksum path.
- No full-document serialization snapshot strategy.
- Node identity, IDs, GUIDs, timestamps, metadata, extension data, and unaffected order must survive Undo/Redo.
- No-op, cancelled, or failed operations do not enter history.
- New forward mutation after Undo clears Redo.
- Reload/discard clears history.
- Dirty state follows history position.
- Default history capacity is 200 logical operations.
- All behavior changes use RED -> GREEN tests.
