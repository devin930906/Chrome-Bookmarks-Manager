## Global constraints

- Windows 10 / Windows 11 x64.
- .NET 10 / WPF / C# / System.Text.Json.
- Only explicit Save may write the loaded source.
- V0.9 supports the already-loaded clear-text Chrome Bookmarks version 1 format only.
- Encrypted Chrome bookmark storage is out of scope.
- No delete-then-move replacement strategy.
- No silent overwrite after external source change.
- No save while any `chrome.exe` process is running.
- No replacement before temp-file validation and verified backup.
- No private real Bookmarks data in GitHub or Actions.
- All behavior changes use RED -> GREEN tests.
- Real Chrome compatibility is proven with a disposable test profile before the production profile is touched.
- Production acceptance requires an independent external backup.
- A failed save must leave the in-memory graph available and dirty/retryable.

### Task 6: Implement backup-first atomic file transaction

**Files:**

- Create `src/ChromeBookmarksManager/Infrastructure/Persistence/IBookmarkFileTransaction.cs`
- Create `src/ChromeBookmarksManager/Infrastructure/Persistence/BookmarkFileTransaction.cs`
- Create typed save/transaction result and exception types
- Create `tests/ChromeBookmarksManager.Tests/Persistence/BookmarkFileTransactionTests.cs`

Required transaction:

1. unique same-directory temp path;
2. writer writes temp;
3. flush/close temp;
4. temp is reopened with reader;
5. temp logical validation passes;
6. unique app-owned backup path is generated;
7. source is copied to backup without overwrite;
8. backup hash + length equal current source;
9. source baseline rechecked;
10. Chrome process rechecked through orchestration;
11. same-volume atomic replace;
12. final source reopened/validated;
13. temp cleanup;
14. verified backup retained.

Backup pattern:

`Bookmarks.ChromeBookmarksManager.YYYYMMDD-HHmmss.fff.bak`

Collision handling must append a deterministic suffix rather than overwrite.

Failure-injection coverage:

- temp create fails;
- temp writer fails;
- temp validation fails;
- backup copy fails;
- backup validation fails;
- source changes between preflight and replace;
- atomic replace fails;
- final validation fails;
- cleanup fails after otherwise safe transaction.

Rules:

- original is never deliberately deleted first;
- pre-replace failures leave source unchanged;
- replacement failure is surfaced with backup path where available;
- post-replace validation failure is a critical recovery-required state;
- no automatic cascading rollback in the first implementation.

Evidence:

- [x] RED transaction/failure tests.
- [x] GREEN implementation.
- [x] Verify source-byte integrity in all pre-replace failures.
- [x] Full regression GREEN.
- [x] Windows Actions GREEN.
- [x] Commit: `feat: add verified atomic bookmark transaction` plus hardening tests; final GREEN Actions #244.
