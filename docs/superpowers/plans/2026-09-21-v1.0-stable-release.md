# V1.0 Stable Personal-Use Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the completed V0.1–V0.9 codebase into a reproducible, verified Chrome Bookmarks Manager 1.0.0 release that closes owner-identified core browser-bookmark-manager parity gaps before stable release.

**Architecture:** Preserve the domain, search, mutation, history, and Safe Save invariants while extending the browser presentation layer where owner acceptance exposes a core browser-manager parity gap. V1.0 combines that parity correction with the existing release-hardening layer: authoritative versioning, production-UI contracts, checksum/asset contracts, explicit 250k measurements, release readiness, tag-driven release workflow, and restarted Windows 10 owner acceptance.

**Tech Stack:** C# / .NET 10 / WPF / XAML / xUnit / PowerShell 7 / Node.js mechanical contract scripts / GitHub Actions / GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-09-21-v1.0-stable-release-design.md`

## 0. Authoritative Product Requirement — Browser Bookmark Manager Functional Parity

> **Owner directive — 2026-09-22. This requirement governs this plan and future bookmark-management work.**

The product exists to replace the need to open the browser's built-in bookmark manager for normal local bookmark management. For core local bookmark-management functionality, standard browser-manager capability is presumed required unless it depends on browser-only cloud/account infrastructure, conflicts with stronger persistence-safety guarantees, or the owner explicitly excludes it.

Do not repeatedly re-ask whether ordinary browser bookmark-manager capabilities are wanted.

### 0.1 Mandatory V1.0 parity correction discovered during owner acceptance

The current V1.0 RC shows only direct `BookmarkUrl` items in the right-hand pane. When a selected folder contains child folders but no direct URLs, the pane appears empty.

The owner explicitly selected **C** for the correction. The right-hand pane must therefore:

- show direct child folders and direct bookmarks together;
- distinguish folder rows from bookmark rows;
- enter a folder by double-click / Enter and synchronize the left tree;
- support right-click folder management;
- support folder rename;
- support folder move;
- support folder delete;
- support folder Drag & Drop;
- support same-parent reorder and cross-folder movement where applicable;
- preserve all existing bookmark rename / URL edit / move / delete / multi-select / batch / Drag & Drop / reorder behavior.

Right-pane and left-tree folder operations must mutate the same domain objects and participate in the same history, dirty-state, Undo/Redo, and Save pipeline.

Exact mixed-selection, keyboard, context-menu, and search-mode semantics must be checked against the current browser bookmark manager before implementation rather than inferred from the current limited right-pane design.

### 0.2 Release gate change

The owner acceptance performed against the pre-parity RC is paused and cannot be used as final V1.0 acceptance evidence.

The sequence is now:

```text
document browser-manager parity requirement
→ design right-pane mixed folder/bookmark behavior
→ TDD implementation
→ full regression/safety/scale verification
→ new Windows RC
→ restart Windows 10 owner acceptance
→ only then merge/tag/release v1.0.0
```

No merge, `v1.0.0` tag, or stable GitHub Release is allowed from the pre-parity RC.

## Global Constraints

- V1.0 remains release-focused, but owner-identified core browser-bookmark-manager parity gaps are release-blocking and must be corrected before final acceptance.
- Target is Windows 10 / Windows 11 x64.
- Runtime target remains `net10.0-windows`, `win-x64`, self-contained, single-file.
- Stable product version is exactly `1.0.0`.
- File version and assembly version are exactly `1.0.0.0`.
- Git tag and GitHub Release are exactly `v1.0.0`.
- Real private Chrome `Bookmarks` files, backups, URLs, titles, queries, and screenshots must never enter Git or GitHub Actions.
- Existing V0.9 Save safety invariants remain unchanged: Chrome-running block, accepted source baseline, validated temp file, verified backup, final source recheck, atomic replacement, post-write validation.
- Existing V0.1–V0.9 feature behavior is preserved unless a release-blocking defect is demonstrated.
- Normal CI keeps bounded synthetic workloads; 250,000-node workloads are explicit release-readiness measurements.
- Ordinary CI artifacts remain short-lived; durable distribution is through GitHub Release.
- Formal release assets are exactly `ChromeBookmarksManager.exe` and `ChromeBookmarksManager.exe.sha256`.
- No new NuGet dependency is permitted unless separately justified under the project dependency policy.
- All behavior/contract changes use RED → GREEN → REFACTOR and end in an independently reviewable commit.

## Review Focus

1. **Tag/project version mismatch:** a tag such as `v1.0.1` against project version `1.0.0` must fail before a GitHub Release can be created. Task 1 pins this with `Verify-V10Version.ps1`.
2. **Tampered checksum or unexpected release file:** a modified EXE, bad checksum line, missing checksum, or extra release payload must fail the release-asset gate. Task 3 pins these cases.
3. **Development-stage UI residue reappears:** stale V0.x wording or empty/disabled production menu placeholders must fail a static UI contract. Task 2 pins this.
4. **Release workflow broadens its payload or trigger:** the workflow must stay tag-driven, writable only for release contents, and must not package V0.9 acceptance helpers. Task 6 pins this with a mechanical workflow contract.
5. **Release measurement environment leaks:** temporary `CBM_*_COUNT` overrides must always be restored/removed, including when one measurement fails. Task 4 pins this with a contract around the runner's `try/finally` cleanup.

```powershell
param(
    [string]$ProjectPath = "src/ChromeBookmarksManager/ChromeBookmarksManager.csproj",
    [string]$ExpectedTag,
    [string]$ExecutablePath
)

$ErrorActionPreference = "Stop"

if (-not (Test-Path -LiteralPath $ProjectPath -PathType Leaf)) {
    throw "Project file not found: $ProjectPath"
}

[xml]$project = Get-Content -LiteralPath $ProjectPath -Raw -Encoding UTF8
$version = [string]$project.Project.PropertyGroup.VersionPrefix

if ($version -notmatch '^\d+\.\d+\.\d+$') {
    throw "VersionPrefix must be semantic MAJOR.MINOR.PATCH, found '$version'."
}

if ($version -ne "1.0.0") {
    throw "V1.0 contract expected VersionPrefix 1.0.0, found $version."
}

if ($ExpectedTag) {
    $expected = "v$version"
    if ($ExpectedTag -cne $expected) {
        throw "Release tag '$ExpectedTag' does not match project version '$expected'."
    }
}

if ($ExecutablePath) {
    if (-not (Test-Path -LiteralPath $ExecutablePath -PathType Leaf)) {
        throw "Executable not found: $ExecutablePath"
    }

    $info = (Get-Item -LiteralPath $ExecutablePath).VersionInfo
    if ($info.FileVersion -cne "$version.0") {
        throw "EXE FileVersion '$($info.FileVersion)' does not equal '$version.0'."
    }

    if ($info.ProductVersion -cne $version) {
        throw "EXE ProductVersion '$($info.ProductVersion)' does not equal '$version'."
    }
}

Write-Host "V1.0 version contract verified: $version"
```

### Task 3: Add canonical SHA-256 and release-asset verification

**Files:**
- Create: `scripts/New-V10ReleaseChecksum.ps1`
- Create: `scripts/Verify-V10ReleaseAssets.ps1`

**Interfaces:**
- Consumes: verified single `ChromeBookmarksManager.exe`.
- Produces: lowercase SHA-256 sidecar; exact two-file release contract.

- [ ] **Step 1: Create checksum generator**

```powershell
param(
    [Parameter(Mandatory = $true)]
    [string]$ExecutablePath
)

$ErrorActionPreference = "Stop"

if (-not (Test-Path -LiteralPath $ExecutablePath -PathType Leaf)) {
    throw "Executable not found: $ExecutablePath"
}

$name = Split-Path -Leaf $ExecutablePath
if ($name -cne "ChromeBookmarksManager.exe") {
    throw "Unexpected executable name: $name"
}

$hash = (Get-FileHash -LiteralPath $ExecutablePath -Algorithm SHA256).Hash.ToLowerInvariant()
$outputPath = "$ExecutablePath.sha256"
Set-Content -LiteralPath $outputPath -Value "$hash  $name" -Encoding ascii
```

- [ ] **Step 2: Create release asset verifier**

```powershell
param(
    [Parameter(Mandatory = $true)]
    [string]$ReleaseDirectory
)

$ErrorActionPreference = "Stop"

$exe = Join-Path $ReleaseDirectory "ChromeBookmarksManager.exe"
$checksum = Join-Path $ReleaseDirectory "ChromeBookmarksManager.exe.sha256"
$files = @(Get-ChildItem -LiteralPath $ReleaseDirectory -File)

if ($files.Count -ne 2) {
    throw "Release directory must contain exactly two files."
}

$names = @($files.Name | Sort-Object)
$expected = @("ChromeBookmarksManager.exe", "ChromeBookmarksManager.exe.sha256")
if (Compare-Object $names $expected) {
    throw "Release directory contains an unexpected asset set."
}

$line = (Get-Content -LiteralPath $checksum -Raw -Encoding ascii).Trim()
if ($line -notmatch '^([0-9a-f]{64})  ChromeBookmarksManager\.exe$') {
    throw "Checksum file format is invalid."
}

$expectedHash = $Matches[1]
$actualHash = (Get-FileHash -LiteralPath $exe -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actualHash -cne $expectedHash) {
    throw "Release EXE SHA256 does not match the checksum file."
}
```
