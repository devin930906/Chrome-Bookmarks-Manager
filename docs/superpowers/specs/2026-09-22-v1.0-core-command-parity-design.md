# V1.0 Chrome Core Bookmark-Manager Command Parity Design

**Date:** 2026-09-22  
**Status:** Approved continuation / release-blocking parity correction  
**Branch:** `feature/v1.0-stabilization`

## Goal

Close the remaining release-blocking gaps between Chrome Bookmarks Manager core local management behavior and Chrome Bookmarks Manager 1.0.0 without weakening the application's stronger Safe Save guarantees.

The application is intended to replace opening Chrome's built-in bookmark manager for normal local bookmark management. Therefore ordinary local bookmark-manager commands are required unless they rely on browser-only tab/account/policy infrastructure or conflict with the product's stronger persistence-safety model.

Current Chrome behavior relevant to this design:

1. Ctrl/Shift selection operates like a file manager over the complete displayed list.
2. Ctrl+A selects the complete displayed list.
3. Delete/Cut/Copy/Open commands operate on the selected item set subject to node editability.
4. Drag initiation accepts an ID list rather than only one bookmark.
5. Ctrl+X / Ctrl+C / Ctrl+V are first-class bookmark-manager shortcuts.
6. Sort by name sorts folders first, then bookmarks, comparing names within each kind.
7. Search results are BookmarkTreeNode IDs returned by the bookmarks search API; no right-pane bookmark-only filtering layer is applied by the manager.
8. Import and export use bookmark HTML.
9. Permanent/special top-level roots are protected from rename/move/remove.

## Existing application invariants that remain authoritative

- No direct domain hierarchy mutation from WPF code-behind.
- All mutations pass through application services and history.
- Permanent Chrome roots remain protected.
- Folder cycle prevention remains mandatory.
- Search/index refresh must preserve identity and avoid unnecessary rebuilds.
- Undo/Redo must restore exact hierarchy/order/counts.
- Source write-back happens only through explicit Safe Save.
- Chrome-running and stale-source write protection remain unchanged.
- No private production bookmark content enters tests, docs, commits, logs, or Actions artifacts.

## Parity decisions

### Mixed selection

The right pane must keep a single ordered selection model over `BookmarkListItemViewModel` rows. Folder presence must no longer collapse the selection to one folder.

Derived compatibility projections may remain:

- `SelectedBookmark`: primary selected bookmark when one exists.
- `SelectedContentFolder`: primary selected folder only when exactly one actionable folder is required by a single-item command.
- bookmark-only arrays used by legacy APIs may continue as projections, not as the authoritative selection.

Single-item commands such as Rename and Edit URL remain disabled for ambiguous multi-selection.

### Mixed batch delete

Delete must accept an ordered set of editable `BookmarkNode` objects containing folders and bookmarks.

Rules:

- Permanent roots are rejected.
- Duplicate references are removed.
- When an ancestor folder and one of its descendants are both present, the descendant is suppressed from the top-level delete set so it is not removed twice.
- Removal occurs in a transaction-like operation with rollback on failure.
- Removed URL/folder counts include full folder subtrees.
- Undo restores exact parent/index structure and identity.
- Redo removes the same nodes again.

### Mixed batch move and Drag & Drop

A batch move must accept ordered `BookmarkNode` items.

Rules:

- Selection order follows displayed order.
- Search-mode positional Drag & Drop remains disabled because search results do not define one mutable sibling sequence.
- Nodes moved within a folder or to another folder preserve their relative order.
- Folder self/descendant cycles are rejected before mutation.
- Redundant descendants of a selected ancestor are suppressed for cross-folder moves.
- Multi-node DnD uses the selected set when the pointer-down row is selected; otherwise it uses only the pointer-down row.
- Before/After targets operate on mixed child order.
- Into is valid only for a folder row.
- Empty-space drop means end of current folder.
- Undo/Redo restores the exact pre/post mixed sequence.

This explicitly retires the V0.6 temporary invariant that Drag & Drop must always be one node.

### Open bookmark

Enter/double-click on a folder continues to navigate into the folder.

For a bookmark, Enter/double-click and context-menu Open must open the URL through the Windows default URL handler.

Safety boundary:

- `http` and `https` are supported for direct launch.
- Unsupported or potentially executable/custom schemes are not shell-launched silently; the UI surfaces a clear error.
- Chrome-specific Open in Incognito / Open in new Chrome window / tab-group commands are BROWSER-ONLY / NOT APPLICABLE to this standalone manager.

### Clipboard

Ctrl+X/C/V and context-menu Cut/Copy/Paste are required.

Architecture:

- Introduce an application clipboard abstraction so tests do not depend on the real Windows clipboard.
- Clipboard payload contains a detached immutable bookmark subtree snapshot, not live domain references.
- Copy leaves source unchanged.
- Cut is modeled as a pending structured payload; the source is not destroyed merely by pressing Ctrl+X. The move/delete occurs only when Paste succeeds, avoiding data loss if the process exits or clipboard changes.
- Paste clones copied content with new Chrome node IDs and GUIDs.
- Cut/paste within the same loaded document moves original nodes when the structured payload can be proven to originate from the current document/version; otherwise it behaves as copy/paste.
- Plain text may be added to the OS clipboard for bookmark URLs, but structured application data is authoritative for hierarchy reconstruction.
- Every paste mutation participates in history and dirty-state tracking.

### Sort by name

Add Sort by name for the current editable folder.

Rules follow Chrome:

- folders first;
- bookmarks second;
- within each kind compare titles using the current UI culture with stable tie handling;
- permanent root itself is not reordered, but its editable children can be sorted;
- no-op sort creates no history entry and does not dirty the document;
- changed sort is one Undo/Redo history step.

### Search folders

Search changes from bookmark-only results to `BookmarkNode` results.

Matching:

- folder: title;
- bookmark: title or URL;
- case-insensitive;
- current-folder scope searches direct displayed children, matching existing scope semantics;
- all-bookmarks scope traverses all three roots and returns matching editable/displayable nodes in deterministic traversal order.

Search remains a projection: it does not mutate hierarchy, and positional DnD remains disabled while search is active.

### Import / export HTML

Support Netscape bookmark HTML compatible with browser bookmark import/export.

Export:

- produces a standalone HTML file without mutating the loaded document;
- exports folders/bookmarks recursively in current order;
- HTML-escapes titles and URLs;
- keeps supported timestamps where practical;
- never exports private data to logs.

Import:

- reads bookmark HTML as untrusted input;
- bounded depth/node count and cancellation are mandatory;
- imported content is appended to a dedicated imported folder under the selected editable destination, matching Chrome's non-destructive import spirit;
- every imported node receives a new Chrome node ID and GUID;
- unsupported attributes are ignored safely;
- malformed HTML fails without partially mutating the document;
- successful import is one undoable mutation.

No new NuGet dependency is introduced solely for HTML parsing; use a small bounded parser tailored to Netscape bookmark HTML and cover it with malformed-input tests.

## UI command surface

Right-pane context menu, top menu, and keyboard routing must converge on the same ViewModel/application commands.

Required shortcuts:

- F2: rename one selected node.
- Delete: delete current mixed selection.
- Ctrl+A: select all displayed rows.
- Escape: deselect rows when not being used to clear an active search.
- Enter: enter one folder or open one bookmark.
- Ctrl+X: cut selected editable nodes.
- Ctrl+C: copy selected nodes.
- Ctrl+V: paste to the selected/current destination when valid.
- Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z: existing Undo/Redo.
- Ctrl+F: existing search focus.

## Compatibility and migration

Legacy bookmark-only APIs remain temporarily available where existing tests depend on them, but new UI flows must use generic node operations. Mechanical V0.x contracts that encode bookmark-only implementation tokens must be updated only when the semantic invariant is preserved or explicitly superseded by this V1.0 parity design.

## Release gate

V1.0 may not be declared stable until all of the following are true:

- mixed folder/bookmark selection is file-manager-like;
- mixed delete and move are undoable;
- multi-node DnD is covered and safe;
- bookmark Open works for safe web URLs;
- Cut/Copy/Paste works with structured bookmark data;
- Sort by name matches folders-first behavior;
- search returns folders and bookmarks where titles match;
- import/export HTML round-trips representative nested data;
- protected roots and cycle checks remain enforced;
- normal CI is green;
- release readiness at 250k/4k/100k is green;
- a new post-parity Windows RC passes owner acceptance.
